The MCP procedurally synthesizes given names (only 13 are in `baseline_given_names`; the generator builds many more via line-aware patterns). The **strong canonical signal is the surname** being in `canon.baseline_surnames` ∪ `canon.lines.name`.

| combat      | 0                                   | —         | —                 | —                |

| ritual      | 1 (`Lio Ren`)                       | 0         | 0                 | **1** (no canonical faction routed → MCP not queried) |

| conversion  | 3                                   | 0         | 2 (Dock Worker Kassia + Warehouse Security Guard — both from `initial_npcs`) | 1 (`npc_07670348` malformed) |

**Two real DM-hallucination paths to note for the README:**
1. **Ritual scenario has no canonical faction** in its seed config → the NPC spawn path skipped the MCP and the LLM made up "Lio Ren". For ritual archetypes intended to demo canonical naming, the seed config needs a canonical faction on the scenario or persistent_npc.
2. **Vendor's `npc_b98d3056`** and **conversion's `npc_07670348`** are empty/malformed IDs — these are DM lifecycle events emitting NPC IDs without bodies. Worth investigating in production code (not a fixture defect; the run captured it faithfully).

**Three by-design author names:** `Jara (Field Medic)`, `Dock Worker Kassia`, `Warehouse Security Guard` all come from config (persistent_vendors / initial_npcs) and are correctly preserved.
